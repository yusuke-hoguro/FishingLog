# Fishing Log ユーザー用プロンプト集

普段は、今の状況に合う依頼文をそのまま送るだけで学習を進められます。AIが `AGENTS.md`、`learning-state.md`、Roadmap、Learning Plan、Progressを確認し、操作対象と現在地を判断します。状態名、Plan ID、Step番号をユーザーが調べる必要はありません。

## 1. 新しいセッションで開始・再開する

```text
Fishing Logの現在地を確認して、続きから進めてください。
```

AIは[共通の再開手順](./learning-workflow.md#8-別セッションで再開する)に従います。Roadmap上の初回は準備、途中なら記録された地点から再開し、Roadmapの完了判定はその条件を満たす場合だけ行います。独立学習では現在Roadmap Stepを検索せず、対象Planと復帰先を別に確認します。ユーザー確認が必要な状態遷移は自動で飛ばしません。どの依頼を使うか迷った場合も、この依頼を使用します。

## 2. 提案されたLearning Planを確定する

```text
このLearning Planで進めます。必要な記録を初期化してください。まだ最初のStepは始めないでください。
```

AIはPlanを確定し、Progressを初期化します。Roadmapに紐づくPlanなら、同じ作業でRoadmapへ関連付け、対象Roadmap Stepを `進行中` にします。

## 3. 現在のPlan内Stepを開始・継続する

```text
現在のStepだけを進めてください。
```

AIはProgressから対象Stepを判断します。ユーザーが考える前に完成回答や完成実装を提示せず、次のStepへも進みません。

## 4. 学習途中で今日は終了する

```text
今日はここまでにします。現在地と次回最初に行うことを記録してください。
```

AIは未完了のStepを `進行中` のままにし、別セッションですぐ再開できる具体的な1アクションをProgressへ残します。

「保留にしてください」と明示した場合は、Planの保留前情報も保存する共通の保留手順を使います。通常の「今日はここまで」と区別します。

## 5. Plan内Stepの完了を判定する

```text
現在のStepの完了条件を確認してください。満たしている場合だけ完了にし、次のStepはまだ始めないでください。
```

## 6. Learning Plan全体の完了を判定する

```text
現在のLearning Plan全体の完了条件を確認してください。満たしている場合だけ完了にし、次に必要な操作をリポジトリの状態から判断してください。まだ次の学習や実装は始めないでください。
```

複数のLearning Planが同じRoadmap Stepにある場合、AIはすべての関連Planを確認します。不足があればRoadmap Stepを完了せず、継続または追加Planを提案します。

## 7. Roadmap Step完了後、次のStepの準備へ進む

Roadmap Stepの完了根拠を確認し、完了承認するときに使います。

```text
このRoadmap Stepを完了にしてください。次のRoadmap Stepは準備だけ進め、学習や実装はまだ始めないでください。
```

## 8. Roadmap外の独立したLearning Planを始める

```text
Roadmap外の独立学習として「<学びたいテーマ>」のLearning Planを提案してください。まず理解度を確認し、まだPlanは確定しないでください。
```

独立Planの親Roadmap Stepは `なし` とし、RoadmapのStatusには影響させません。

独立学習の入れ子は扱いません。すでに独立学習中の場合は、その学習を終了または保留してRoadmapへ戻ってから、別の独立学習を提案します。AIはその順序を案内し、無断で切替・終了・保留・復帰を行いません。

## 9. Learning Planを変更する

```text
現在のLearning Planを変更したいです。現在地と完了済みの記録を確認し、変更理由、影響範囲、修正案を示してください。私が確認するまで変更や次のStepを開始しないでください。
```

Planの分割・統合・置換もこの依頼で開始できます。AIは完了済み記録を残し、RoadmapとProgressへの影響も確認します。

## 10. Roadmapを変更する

```text
Roadmapを変更したいです。現在のPlanとProgressへの影響を確認し、変更案を示してください。私が確認するまでRoadmapや関連ファイルを変更しないでください。
```

## 11. 記録の矛盾や欠損を点検・復旧する

```text
学習記録の整合性を確認してください。矛盾や欠損があれば学習を進めず、問題、根拠、復旧案を示してください。一意に直せない内容だけ私に確認してください。
```

通常は1の開始・再開依頼でも同じ整合性チェックを行います。この依頼は、記録に問題があると感じたときに明示的な点検だけを行うためのものです。

## 困ったとき

どれを使うか迷った場合は、1の「Fishing Logの現在地を確認して、続きから進めてください。」を送ってください。AIがリポジトリ内の記録から次に必要な操作を判断します。矛盾があれば勝手に進めず、復旧案を提示します。
